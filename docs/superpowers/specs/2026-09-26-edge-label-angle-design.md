# 连线标签的旋转入口（`style.label.angle`）

日期：2026-09-26 ｜ 关联：下游 `ice-agent-console` 的《上游缺口清单》第 18 条

## 背景

连线标签的位置由 `getLabelPosition()` 钉死在折线上（2 点取中点、多点取中间折点），
标签盒是**横排**的：宽 = 字宽 + 8、高 = 字号 + 8。于是：

- **竖线上的长标注**无论往左还是往右挪，盒子都可能仍然压着线。
  实测下游一条 `DN1000 污水` 的盒子 **79px 宽**，往右挪 12px 之后左边还有 ~28px 盖在线上；
  要不旋转就彻底离开线得挪 40+px，那就飘得离管子太远了。
- 制图惯例恰恰相反：**竖向标注自下而上读**，标签贴着管子走。

`style.label.offset`（2026-09-18 加）解决了"标签压在别的东西上"，但它解决不了
"标签横排时太宽"—— 这是两个自由度：**位置**与**朝向**。

## 决定

加一个字段：`style.label.angle`（**弧度**，绕标签中心旋转；与 `arrowAngel` 同一口径）。

- 语义：只转标签，不动折线；绕**标签中心**转（`translate(x, y) → rotate(θ)`）。
- 非法值（非有限数）当 0，不抛错 —— 与 `offset` 同一条规矩。
- 默认**不写这个键**（零角度没有表达价值，写了会进 state 与快照）。

**`__labelMetrics()` 返回旋转后的 AABB**（`|w·cosθ| + |h·sinθ|` / `|w·sinθ| + |h·cosθ|`），
因为它有三个消费者，其中两个只能吃 AABB：

| 消费者 | 需要什么 | 不这么做的后果 |
|---|---|---|
| 画布 `drawLabel()` | 未旋转的 `w / h` + 角度 | — |
| 包围盒（上屏快照盒 / 脏区擦除盒 / 离屏缓存范围） | **AABB** | 转 90° 后擦除盒窄一半 → 画面留残影 |
| `getLabelRenderInfo()`（SVG 导出） | 未旋转的 `w / h` + `angle` | 用 AABB 画矩形 → 导出一个"横躺的盒子" |

所以 `__labelMetrics()` 同时给出两组值：`halfW / halfH`（AABB，喂包围盒）与 `w / h`（未旋转，喂绘制与导出）。

## 非目标

- **不做自动判定**（引擎不知道"这段线算不算长""用户要不要竖排"）—— 由应用层算：下游按
  "段是竖的 + 段长装得下标注"决定 `angle = -π/2`，短竖段不转（转了字会戳出管子两头）。
- 不做竖排文字（逐字堆叠）—— 那是另一种排版，与"整块旋转"不同需求。

## 验收

- 单测：`tests/link/polyline-label-angle.test.ts`（AABB 90°/45°、非法值当 0、运行时改角度、
  画布调用序列 `translate → rotate → 未旋转盒`、不转时序列不变）。
- 导出：`tests/export/svg-export.test.ts` 增一条（`<g transform="rotate(-90 x y)">` + 未旋转尺寸的 rect）。
- 下游回归：`npm run regression:family`（改的是 `src/` 核心渲染，按脚本判定会对全家族跑 e2e）。
